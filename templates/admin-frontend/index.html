Overview

          
Eventer collects campus events from websites (scrape sources), matches them to buildings on the Dartmouth map, and serves them to the mobile app. As an admin, you review scraped data, fix bad locations, and add events that aren't on any website.

          

            
Active

            
Event is visible in the mobile app. Inactive events are hidden but kept in the database.

            
Verified

            
A staff member has reviewed the event and confirmed it looks correct. Unverified events still show in the app unless deactivated.

            
Scraper

            
The automated job that reads event websites every few hours and creates/updates events.

            
Alias

            
An alternate name for a building (e.g. "Collis" for "Collis Center"). The scraper uses aliases to figure out where an event is.

          

        


        

          
Dashboard

          
Your at-a-glance health check. Use it to spot problems before users do.

          

            
Events Today

            
Active events starting today (UTC). A sudden drop may mean a scrape failed.

            
Active This Week

            
Events happening in the next 7 days that are still active.

            
Scrape Health (24h)

            
Percentage of scrape runs in the last 24 hours that succeeded. Below 100% — check Scrape Sources and their logs.

            
Unresolved Locations

            
Events where the scraper couldn't match a location string to a building. Click through to Unresolved Locations to fix them.

            
Recent Scrapes

            
Latest run per source: status (success, partial, failed) and a short log message.

          

        


        

          
Events Manager

          
All events in the system. Scraped events appear here automatically; you can also create events by hand.

          
Table columns

          

            
Name

            
Event title shown in the app. Click the cell to edit inline, then click Save on that row.

            
Category

            
Event type (e.g. free_food, academic_lecture). Controls icon and color in the app.

            
Start

            
When the event begins (stored in UTC).

            
Active

            
✓ = visible in app. ✗ = hidden (soft delete).

            
Verified

            
✓ = you've reviewed it. Use Bulk Verify after checking a batch of scraped events.

          

          
Actions

          
    
            
  • Select rows — click row checkboxes, then use Bulk Verify or Bulk Deactivate.
    • 
            
  • Bulk Verify — marks selected events as reviewed.
    • 
            
  • Bulk Deactivate — hides selected events from the app without deleting them.
    • 
            
  • New Event — creates a manual event (prompts for a name; set other fields in the table after).
    • 
          

        


        

          
Unresolved Locations

          
When the scraper reads a location like "Mysterious Hall" and can't match it to any building or alias, the event lands here with the raw location string.

          
How to fix one

          
    
            
  1. Find the correct building in Buildings Manager and note its ID number.
    2. 
            
  2. In the Assign Building ID column, type that ID.
    3. 
            
  3. Click Assign.
    4. 
            
  4. If prompted, choose Yes to save the location string as a new alias — future scrapes will auto-match it.
    5. 
          

        


        

          
Buildings Manager

          
Buildings must match the campus map (GeoJSON) in the mobile app. Each building has an official name, coordinates, and optional aliases.

          

            
Official Name

            
Canonical name (e.g. "Baker-Berry Library"). Should match the map footprint name.

            
Lat / Lng

            
Map pin coordinates for the building center.

            
GeoJSON ID

            
Identifier linking this record to the map asset in the mobile app. Must stay in sync with GeoJSON name / feature id.

            
Aliases

            
Comma-separated nicknames shown in the table. Click Aliases on a row to add or remove them.

          

          
Alias sources

          

            
admin

            
You added it manually.

            
scraper

            
Created automatically from scrape data.

            
student_report

            
Reported by a student (future use).

          

          
New Building — adds a placeholder; update name, coordinates, and GeoJSON ID before relying on it.

        


        

          
Suggest Aliases

          
A ranked list of location strings that failed to match during scraping, with how many events used each string. Use this to spot patterns — e.g. if "Hop" appears 12 times, add it as an alias for Hopkins Center in Buildings Manager.

          
This page is read-only. To act on a suggestion, go to Buildings Manager → Aliases on the correct building, or fix events in Unresolved Locations.

        


        

          
Scrape Sources

          
Each source is a website Eventer reads on a schedule (default: every 3 hours).

          

            
Label

            
Human-readable name (e.g. "Dartmouth Mirror Events").

            
URL

            
Page to fetch. For local testing, URLs starting with file:// read from a file in the repo.

            
Interval (hours)

            
How often to scrape. Changing this updates the background schedule automatically.

            
Active

            
When unchecked, scraping is paused for this source.

            
Selector Config (JSON)

            
CSS selectors telling the scraper where to find each field on the page. Keys:

          

          
{
  "container": ".event",        // wrapper for each event on the page
  "event_name": ".title",       // event title
  "start_time": ".start",       // start date/time text
  "end_time": ".end",           // end date/time (optional)
  "location": ".location",      // building/room string
  "description": ".description",
  "source_url": ".link",        // link to event detail page
  "default_category": "free_food"  // fallback if no category on page
}

          
Buttons

          
    
            
  • Save — stores changes and updates the scrape schedule.
    • 
            
  • Run Now — triggers an immediate scrape (requires Celery worker running).
    • 
            
  • View Logs — shows the most recent scrape result and any error messages.
    • 
          

        


        

          
Common Workflows

          
Daily check

          
    
            
  1. Open Dashboard — confirm Scrape Health is 100% and Unresolved Locations is low.
    2. 
            
  2. Review Events Manager — bulk-verify events that look correct.
    3. 
          

          
Fix a bad location from scraping

          
    
            
  1. Go to Unresolved Locations.
    2. 
            
  2. Assign the correct building ID and save as alias if prompted.
    3. 
          

          
Add an event not on any website

          
    
            
  1. Events Manager → New Event.
    2. 
            
  2. Edit category, times, and building in the table; click Save on the row.
    3. 
            
  3. Mark it Verified when done.
    4. 
          

          
Add a new event website

          
    
            
  1. Scrape Sources → New Source.
    2. 
            
  2. Enter the URL and write selector config JSON for that page's HTML structure.
    3. 
            
  3. Save, then Run Now and check logs. Fix selectors if status is failed or partial.
    4.
